# WIRE TO WIRE — V21 final fictional industry identity certification

## Certified scope and strict live-world boundary

This is a **repeatable, executable quality gate** for the already delivered V3–V20 fictional naming, approved identity, durable organization continuity, succession, leadership and capacity engines.

**V21 does not populate, replace, reset or migrate the January 1, 1999 playable game.** It never creates historical horses, edits pedigrees, writes game saves, edits a UI, alters licensed records or invents family/ownership relationships. Its names, people, firms and occupancy counts exist only inside disposable in-memory test stores.

This certification is intentionally NOT a sign-off on separate gameplay finances, horse pedigree research, historical data completeness, human-record evidence, racing movement, shipping or real-time application performance.

## Repeatable verification

```sh
npm run certify:fictional-industry
node --test tests/1999-fictional-industry-final-certification-v21.test.mjs
npm test
```

The CLI prints one JSON certificate containing the tested years, the established 1999 fingerprint, number of person/business registrations, continuation events, quality-audit years, archive-recovery outcome, impossible-management findings and a deterministic SHA-256 of a representative certified projection.

It is a verification utility, **not** a scheduled generator. Running it cannot allocate a single horse or register an owner in a live career.

## What the integration certificate proves

1. **1999 reference immutability.** It reconstructs the established original V7 1999 test cohort using the already locked `Eras-Compatibility` fixture. The expected manifestation is fingerprint `64afc00b`, 445 people and 352 organizations. No replacement names or era-specific mutations are accepted.
2. **1999–2099 progress, all 101 individual years.** A detached V12 naming service issues synthetic batches incrementally. Each approved person is registered through V18 using the original permanent ID, name, primary surname, birth year and cultural-origin metadata. Each new approved ownership company, stable and farm enters through V19 typed approval. V16/V17 stores its own revision-guarded journal events; nothing is created by a missing business ID lookup.
3. **Organizational and career continuity.** New companies receive explicit, role-specific, V20 operating capacities. One established racing stable carries its original name and ID through two future trainer appointments. Its original trainer retires only after relinquishing active duties. No renamed or second stable is created.
4. **International and generational quality.** Nine independent, larger cohorts spanning the pre-2000 baseline, the 2000–2019 transition, 2020–2049, 2050–2079 and 2080–2099 eras pass the existing V14 naming quality and V15 organizational audits. Future names retain editorial provenance distinct from observed historical or Social Security data.
5. **Aging and staffing risk.** `fictional-industry-readiness-v21.mjs` reads the actual approved people and organizations to identify absent managers, retired/unavailable leadership, wrong professional roles and implausible active ages. An organization retains its identity, but **must not be treated as freely usable capacity** until genuinely staffed. The V20 reuse index now suppresses such capacity and reports it separately. This check does not invent successors or automatically retire anyone.
6. **Compact capacity and owner reuse.** V20's separate 100,000-horse aggregate capacity tests remain part of the full suite: it uses already existing businesses and proposes only counts, never population or horse assignment. All new V20/V21 cursors are small and history stays in the append-only journal.
7. **Recovery without drift.** V12 signed naming bundles and V17 organization archives are independently restored into previously empty stores. All initial organization names, cross-era IDs, retiring trainer, succession events, current managers and approved cultural identity data survive. The same synthetic seed and events must reproduce the same SHA-256 certificate, not merely a plausible-looking population.

## Readiness checks are advisory, not fake employment actions

`auditFictionalIndustryReadinessV21({continuity,year,sampleLimit})` is a one-pass, bounded-sample read-only audit. It returns aggregate issue counts and a small set of actual affected organization IDs. Its age admissibility range is the existing V16 career rule (18 through 100 at the assessed year), not a claimed legal retirement age. An old owner may still be associated with the business historically, but cannot be assumed eligible for new active assignments at an implausible age.

`assessFictionalOrganizationReadinessV21({organization,getPerson,year})` checks a single existing firm and returns only sourced reasons. It does not infer bloodlines, family membership, nationality or inheritance from surnames. Unstaffed training centers or farms are not automatically considered viable merely because they have configured horse slots.

The V20 read-only reuse index excludes ineligible active businesses from available capacity, counts `notReadyOrganizations` and `blockedCapacitySlots`, and still preserves the full permanent business record and original history.

## Historical-source / editorial separation

The 1999 baseline is a locked *fictional naming* regression fixture; it is not a historical evidence database. V13/V14 2050–2099 cultural naming rules are labeled editorial projections, not invented real demographic statistics. V21 uses this evidence distinction throughout and refuses to imply any verified real-world legal identity, social relationship, residence or company existence.
